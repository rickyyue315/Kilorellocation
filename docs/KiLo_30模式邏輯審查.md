# KiLo 調貨系統：30 模式邏輯審查（v2.38.5）

> 產生日期：2026-11-01　｜　核對方式：程式碼逐行 + 實際執行模擬　｜　30 模式 / 9 家族 / 2 保底主體

## 0　一頁看懂

管線：Excel 上載 → 前處理 → 保底主體（Safety / Turnday）→ 分組（Article+OM 或 Article）→ 來源識別 → 接收識別 → 配對 → 後處理輸出。

三種需求：缺貨（Safety）、補 0（total ≤ 1 或 0）、Target（指定追加量）。模式之間最大的差別是「只認哪一種需求」。

## 1　保底主體：Safety vs Turnday

30 個模式共用同一個保底概念：Safety 是上載檔固定值，Turnday 是按日銷速算出的浮動值。切換主體只改 `Safety Stock` 欄（原值備份至 `Original Safety Stock`，另加 `Daily Sold Rate`），配對邏輯不變。

**Turnday 三步（數據日期 2026-08-15、N = 14 為例）**

1. 覆蓋日數 = 7 月 31 日 + MTD 15 日 = **46 日**（上月日數 + MTD 數據日期日號）
2. 日銷速 = Effective Sold 92 件 ÷ 46 日 = **2.0 件/日**（Last Month 62 + MTD 30）
3. 保底 = ceil(2.0 × 14) = **28 件**（N 可選 3–60，預設 14；零銷量 → 0）

**同一間店，兩種保底（N = 14）**

| 店舖 | 近 46 日銷量 | 日銷速 | Safety | Turnday | 效果 |
|---|---|---|---|---|---|
| 快銷店 | 92 件 | 2.0 件/日 | 5 | 28 | 更保守・防斷貨 |
| 慢銷店 | 23 件 | 0.5 件/日 | 5 | 7 | 保底下降・釋放庫存 |
| 零銷量店 | 0 件 | 0 件/日 | 5 | 0 | 存貨可全數轉出（清死貨） |

**受影響模式**

| 類別 | 模式 | Turnday 下的變化 |
|---|---|---|
| 全面受影響 | A / A1 / B / C / C2 / B2 系列 / E1 / E1b / E2 / D / D2 / ND1 / ND2 / 精簡 SKU ×2 | 轉出保底與接收目標全部改用 T（S → T） |
| 部分受影響 | C1、F / F2 / F3、NST、ND3 / ND4 | 只有接收端的 Safety 觸點切換（例：補 0 目標 max(S×0.5,3) → max(T×0.5,3)） |
| 上限語義 | B2 系列 / E1 / 精簡 SKU | 接收上限 max(S×2,3) → max(T×2,3)，即 2N 日用量；補 0 目標變成 N/2 日用量 |

固定保底不受主體影響：C1 淨存 > 2、F3／NST 保留 2 件、NST 75% 上限、ND3／ND4 保留 3 件。

## 2　共通規則

- ND 預設只出不入；例外：ND1–ND4 互轉、F/F2/F3/NST 的 Target ND。
- 同一 SKU 的來源店不可同時做接收店；RF 最高有效銷量店受保護（部分模式）。
- Windy 出貨只可到 Windy；HD 不可轉到 HA／HB／HC。
- 所有可轉量以淨庫存封頂；總庫存 = 淨庫存 + 在途；MOQ 不參與計算。
- 後處理只合併同一來源的多條 1 件線；D／D2 不做單件合併。

## A / A1 / B — 基礎加減法

以「總庫存 − Safety Stock」為可轉出基礎，再用百分比上限封頂；接收端只補緊急與潛在缺貨。三個模式的分別在「百分比上限」與「如何處理來源餘數」。

| 模式 | 可轉出上限 | 轉後可否低於 Safety | 特殊處理 |
|---|---|---|---|
| A | max(總×20%, 2) | 否（單件上調例外） | 單件上調至 2 |
| A1 | 同 A | 否（單件上調例外） | 消除來源剩 1 件 |
| B | max(總×50%, 2) | 只在有在途時 | 無 |

### A　保守轉貨

*寧可少調；除單件上調外，不讓來源跌破 Safety。*

**何時用**：日常補貨、想嚴格控制風險；來源店仍有陳列需要，不願一次清太多。

**輸入**：基本欄位　**參數**：—

**來源**

- RF：總庫存 > Safety，且有效銷量 < 同組 RF 最高銷量。
- ND：淨庫存 > 0 全數轉出（優先級 1），不設上限。
- 最高銷量店受保護，不會被選為 RF 來源。

**可轉量**

- 可轉 = min(總庫存 − Safety, max(總庫存×20%, 2), 淨庫存)。
- 轉出後剩餘必須 ≥ Safety；否則不轉。
- 若算出的可轉量 = 1 且轉後仍餘 ≥3 件，上調至 2 件（刻意放寬 Safety 1 件）。

**接收**

- RF 淨庫存 = 0 且有銷量 → 補至 Safety（緊急，優先 1）。
- RF 總庫存 < Safety → 補差額至 Safety（潛在，優先 2）。
- 不處理 Target、不補 0、不超補。

**配對次序**

1. ND 轉出 → 緊急缺貨
2. ND 轉出 → 潛在缺貨
3. RF 過剩 → 緊急缺貨
4. RF 過剩 → 潛在缺貨

**後處理**

- 單件合併／Rebalance（同一來源多條線時）
- 按件數與優先級分 🔴/🟡/🟢

**模擬範例（AB）**

| 店舖 | RP | Net | Pending | Safety | LM+MTD | Type | Target | ALL |
|---|---|---|---|---|---|---|---|---|
| HC001 | RF | 10 | 0 | 4 | 1+0 |  |  |  |
| HC003 | RF | 10 | 0 | 4 | 3+0 |  |  |  |
| HA002 | RF | 0 | 0 | 8 | 4+2 |  |  |  |

| 來源 | 接收 | 件數 | 來源類型 | 接收類型 | 來源轉後 |
|---|---|---|---|---|---|
| HC001 | HA002 | 2 | RF過剩轉出 | 緊急缺貨補貨 | 8 |
| HC003 | HA002 | 2 | RF過剩轉出 | 緊急缺貨補貨 | 8 |

**計算**：HC001：10 − 4 = 6；10×20% = 2 → min(6, 2, 10) = 2，轉後 8 ≥ Safety 4。HC003 同樣 2。HA002 欠 8，實收 4，缺口 4（無其他來源）。

**不能處理的情景**

- 【設計】只補到 Safety，不會補 Target；缺貨店不會超補。
- 【設計】ND 只出不收；ND 來源不受 20% 上限。
- 【邊界】淨 4、Safety 3 時，單件上調會轉 2 件，來源剩 2（低於 Safety 1 件），但 Source Type 仍標「RF過剩轉出」。
- 【資料】同組 RF 銷量全部相同或全為 0 時，最高銷量保護失效（max = ∞），所有 RF 都可出貨。
- 【設計】不考慮 MOQ、箱規、陳列容量。

### A1　保守轉貨（轉出店舖不餘存貨 1 件）

*與 A 相同，但不容許來源剛好剩 1 件。*

**何時用**：ND 店或細店轉出後經常剩 1 件，造成「有貨但賣不出、又不再補」的尾貨。

**輸入**：基本欄位　**參數**：—

**來源**

- 完全沿用 A 的來源判斷與 20% 上限。

**可轉量**

- 先按 A 計算轉出量。
- 若轉後來源剩 1 件：優先 +1 件（接收上限放寬至 Target+1）；不可行時 −1 件。
- 後處理會再掃描一次，把仍剩 1 件的來源補 1 件到最高銷量接收店。

**接收**

- 與 A 相同：緊急（優先 1）→ 潛在（優先 2）。

**配對次序**

1. ND 轉出 → 緊急缺貨
2. ND 轉出 → 潛在缺貨
3. RF 過剩 → 緊急缺貨
4. RF 過剩 → 潛在缺貨

**後處理**

- A1 專屬：來源剩 1 → 接收方 +1
- 其餘同 A

**模擬範例（A1）**

| 店舖 | RP | Net | Pending | Safety | LM+MTD | Type | Target | ALL |
|---|---|---|---|---|---|---|---|---|
| HA010 | ND | 6 | 0 | 0 | 0+0 |  |  |  |
| HA020 | RF | 0 | 0 | 5 | 3+0 |  |  |  |

| 來源 | 接收 | 件數 | 來源類型 | 接收類型 | 來源轉後 |
|---|---|---|---|---|---|
| HA010 | HA020 | 6 | ND轉出 | 緊急缺貨補貨 | 0 |

**計算**：HA010 ND 6 件、HA020 欠 5：A 轉 5，來源剩 1；A1 偵測剩 1，把接收上限放寬至 5+1 = 6，轉 6，來源剩 0。

**不能處理的情景**

- 【設計】只消除「剩 1」，剩 2、3 件不會處理。
- 【風險】接收方可以超出 Target 1 件；品質檢查不涵蓋這類 Target，報表上不會顯示超收。
- 【邊界】來源可轉量不足 +1 時會改為 −1，可能令缺口由 0 變 1。
- 【設計】只避免「剛好 1 件」，不保證來源清零。

### B　加強轉貨

*把上限由 20% 放寬到 50%，允許動用 Safety。*

**何時用**：滯銷品堆積、需要積極騰出空間；可接受來源店短期低於 Safety。

**輸入**：基本欄位　**參數**：—

**來源**

- RF：總庫存 > Safety，且非最高銷量。
- ND：淨庫存 > 0 全數轉出。

**可轉量**

- 可轉 = min(總庫存 − Safety, max(總庫存×50%, 2), 淨庫存)。
- 若在途（Pending Received）> 0，轉後淨庫存可以低於 Safety，Source Type 標為「RF加強轉出」。
- 在途 = 0 時，數學上仍會保留 Safety，不會出現「加強轉出」。

**接收**

- 與 A 相同：緊急 → 潛在，补至 Safety。

**配對次序**

1. ND 轉出 → 緊急
2. ND 轉出 → 潛在
3. RF 過剩 → 緊急
4. RF 過剩 → 潛在
5. RF 加強 → 緊急
6. RF 加強 → 潛在

**後處理**

- 單件合併／Rebalance
- 優先級分組

**模擬範例（AB）**

| 店舖 | RP | Net | Pending | Safety | LM+MTD | Type | Target | ALL |
|---|---|---|---|---|---|---|---|---|
| HC001 | RF | 10 | 0 | 4 | 1+0 |  |  |  |
| HC003 | RF | 10 | 0 | 4 | 3+0 |  |  |  |
| HA002 | RF | 0 | 0 | 8 | 4+2 |  |  |  |

| 來源 | 接收 | 件數 | 來源類型 | 接收類型 | 來源轉後 |
|---|---|---|---|---|---|
| HC001 | HA002 | 5 | RF過剩轉出 | 緊急缺貨補貨 | 5 |
| HC003 | HA002 | 3 | RF過剩轉出 | 緊急缺貨補貨 | 7 |

**計算**：HC001：min(6, max(5,2), 10) = 5；HC003：min(6, 5, 10) = 5，但 HA002 只欠 3 → 轉 3。合計 8，缺口 0。

**不能處理的情景**

- 【風險】「可下探 Safety」只在有 Pending Received 時成立（例：淨 6、在途 4、Safety 4 → 轉 5、剩 1）；純淨庫存情況下 B 仍會保留 Safety，與宣傳有落差。
- 【設計】只補 Safety，不補 Target；缺貨店補滿即停。
- 【邊界】最高銷量保護失效時（全組同銷量或全 0），所有 RF 都可出貨。
- 【設計】ND 全轉，可能一次清空 ND 店。

## B2 家族 — B 特別模式（同 OM）

在 B 的基礎上加入三個開關：ND 全轉、Type=L 全轉或保留 2 件、Type=T 不可出貨；接收端按遊客區／混合型店舖排序，上限 Safety×2。

| 模式 | Type=L | Type=T 出貨 | 跨 OM |
|---|---|---|---|
| B2 | 全轉 | 可 | 否 |
| B2a | 全轉 | 不可 | 否 |
| B2L | 保留 2 件 | 可 | 否 |
| B2La | 保留 2 件 | 不可 | 否 |

### B2　附加 B（特別模式）

*ND 與 Type=L 全轉，接收端優先遊客區／混合型。*

**何時用**：需要同時清 ND 與 Local 店低銷量貨，並優先補遊客區高銷量店。

**輸入**：基本欄位、Type　**參數**：—

**來源**

- ND：淨庫存 > 0 全轉（優先 1）。
- Type=L 且 max(Last Month, MTD) ≤ 2：淨庫存全轉（優先 2）。
- 其餘 RF：按 B 規則（50% 上限、非最高銷量）。

**可轉量**

- ND／L：全數淨庫存。
- RF：min(總−Safety, max(總×50%,2), 淨庫存)。

**接收**

- 只收 RF，且總庫存 < Safety。
- Type=T 有銷量 → 優先 1；Type=M 有銷量 → 優先 2；T 無銷量 → 3；M 無銷量 → 4；其他 → 4。
- 需求量 = Safety − 總庫存；上限 max(Safety×2, 3)。

**配對次序**

1. ND 全轉 → P1
2. ND 全轉 → P2
3. RF 過剩 → P1
4. RF 過剩 → P2
5. L 全轉 → P1
6. L 全轉 → P2
7. RF 加強 → P1
8. RF 加強 → P2

**後處理**

- 單件合併（同一來源多條線）
- 接收量按店累計，達上限即停

**模擬範例（B2L）**

| 店舖 | RP | Net | Pending | Safety | LM+MTD | Type | Target | ALL |
|---|---|---|---|---|---|---|---|---|
| HL001 | RF | 8 | 0 | 2 | 1+0 | L |  |  |
| HL002 | RF | 2 | 0 | 2 | 0+0 | L |  |  |
| HT001 | RF | 0 | 0 | 12 | 6+0 | T |  |  |

| 來源 | 接收 | 件數 | 來源類型 | 接收類型 | 來源轉後 |
|---|---|---|---|---|---|
| HL001 | HT001 | 8 | Local店舖全轉出 | 遊客區店舖 高銷量優先 | 0 |
| HL002 | HT001 | 2 | Local店舖全轉出 | 遊客區店舖 高銷量優先 | 0 |

**計算**：HL001（L，8 件）與 HL002（L，2 件）全轉；HT001 欠 12、上限 24，實收 10（8+2），仍有缺口 2。

**不能處理的情景**

- 【高】只服務優先 1–2（Type=T/M 且有銷量）。優先 3–4（零銷量 T/M、Type=L、其他 Type）永遠不會被配對；即使庫存 0 也不會補。
- 【設計】Mix 保護只比較總銷量：M 店銷量高於目標店即不可出貨，即使目標店急需。
- 【設計】接收上限 Safety×2（最少 3），細店可能一次收過多。
- 【設計】Type=L 全轉，可能清空仍有陳列需要的 Local 店。
- 【資料】Type 欄空白 → 全部落入優先 4 → 0 建議；上載時只檢查欄位存在，不檢查內容。

### B2a　附加 B2a（T 遊客鋪不出貨）

*B2 加上「Type=T 不可作為來源」。*

**何時用**：遊客區店舖需要保留貨源，不應被抽走。

**輸入**：基本欄位、Type　**參數**：—

**來源**

- 同 B2，但 Type=T 的店舖一律不可出貨（ND／L／RF 皆然）。

**可轉量**

- 同 B2。

**接收**

- 同 B2：T 有銷量 P1、M 有銷量 P2；上限 max(S×2,3)。

**配對次序**

1. ND 全轉 → P1
2. ND 全轉 → P2
3. RF 過剩 → P1
4. RF 過剩 → P2
5. L 全轉 → P1
6. L 全轉 → P2
7. RF 加強 → P1

## C 家族 — 重點補 0

不是按比例抽貨，而是先鎖定「幾乎沒有貨」的店舖，再把少量貨集中補過去。C 與 C2 仍會回落一般缺貨；C1 只補門檻內的店。

### C　重點補 0

*先救「幾乎無貨」的店，每店最多抽 3 件（可調 3–10）。*

**何時用**：店舖庫存 0–1 件，需要少量、多次補貨，避免一次抽乾來源。

**輸入**：基本欄位　**參數**：—

**來源**

- ND：淨庫存 > 0 全轉（優先 1）。
- RF：總庫存 > Safety 且非最高銷量（優先 2）。

**可轉量**

- 可轉 = min(總−Safety, 上限, 淨庫存)。
- 上限 = min(int(總×30%), 自訂上限)；比例為 0 時直接用自訂上限（預設 3）。

**接收**

- RF 總庫存 ≤1 且（Safety>0 或有效銷量>0）→ 目標 max(Safety×0.5, 3)，優先 1。
- 其餘回落一般規則：淨 0 有銷量 → 補 Safety（緊急）；總 < Safety → 補差額（潛在）。

**配對次序**

1. ND → 補 0
2. ND → 緊急
3. ND → 潛在
4. RF 過剩 → 補 0
5. RF 過剩 → 緊急／潛在
6. RF 加強 → 補 0
7. RF 加強 → 緊急／潛在

**後處理**

- 單件合併（同一來源多條線）
- 每店累收達 target 即停

## D / D2 — 清貨轉貨

把 ND 店舖的貨清往同 OM 的 RF 缺貨店，並刻意避免來源最後剩 1 件。D 與 D2 的分別是「ND 是否只限無銷量」與「RF 可否出貨」。

| 模式 | ND 來源 | RF 來源 | 接收店數限制 |
|---|---|---|---|
| D | 無銷量＋有銷量 | 可（B 規則） | 不限 |
| D2 | 只無銷量 | 不可 | 不限／2 間／2 間優化 |

### D　清貨轉貨

*把 ND 貨清往同 OM 的 RF 缺貨店，避免剩 1 件。*

**何時用**：ND 店積壓、需要騰空；同 OM 有 RF 店缺貨。

**輸入**：基本欄位　**參數**：—

**來源**

- ND 淨 > 0：Last Month = MTD = 0 → 「ND清貨轉出」；有銷量 → 「ND轉出」。兩者都全數轉出（優先 1）。
- RF：按 B 規則（總 > Safety、非最高銷量、50% 上限）。

**可轉量**

- ND：全數淨庫存；若轉後剩 1 件，會 +1 或 −1 避開。
- RF：min(總−Safety, max(總×50%,2), 淨)。

**接收**

- RF 淨 0 有銷量 → 補 max(Safety, 2)（緊急，優先 1）。
- RF 總 < Safety → 補至 Safety（潛在，優先 2）。
- 排序：同級按總銷量降序。

**配對次序**

1. ND 清貨 → 緊急／潛在
2. ND 轉出 → 緊急／潛在
3. RF 過剩 → 緊急／潛在
4. RF 加強 → 緊急／潛在

**後處理**

- D 家族排除單件合併
- ND 餘 1 件自動 ±1

- 【設計】D 家族排除單件後處理，可輸出 1 件線（同一來源有多條線時亦不會合併）。
- 【設計】只配對同 OM；跨 OM 需求要靠其他模式。

### D2　清貨轉貨（ND 限定）

*只清無銷量 ND，RF 只收不出。*

**何時用**：只想清走死貨，不願動用 RF 貨源。

**輸入**：基本欄位　**參數**：—

**來源**

- 只收 ND、Last Month = MTD = 0、淨 > 0 → 全數轉出。
- 有銷量 ND 與所有 RF 一律不作來源。

**可轉量**

- ND：全數淨庫存；避免轉後剩 1 件。

**接收**

- 同 D：RF 淨 0 有銷量 → max(Safety,2)；總 < Safety → 補至 Safety。

**配對次序**

1. ND 清貨 → 緊急／潛在

**後處理**

- 每來源最多 2 間（可選）
- 優化版 target ×2
- 排除單件合併

## E 家族 — 強制轉出

只處理 ALL 欄有標記的貨品，將來源淨庫存全數轉出，不理 Safety、銷量與 Target。接收端只按「Safety×2（最少 3）」的容量決定收多少。

| 模式 | 配對範圍 | 接收排序 | 跨 OM |
|---|---|---|---|
| E1 | 同 OM | 無（按陳列次序） | 否 |
| E1b | 同 OM | Type=T → M → 其他 | 否 |
| E2 | 同 OM 優先，再跨 OM | 無 | 是 |

### E1　強制轉出（僅同 OM）

*ALL 標記的貨，盡量全數轉出。*

**何時用**：需要清走指定貨品（例如退倉、轉陳列、換季），不容許留在原店。

**輸入**：基本欄位、ALL　**參數**：—

**來源**

- ALL 欄非空且淨庫存 > 0 → 全數轉出（優先 1）。

**可轉量**

**配對次序**

**後處理**

- 單件合併
- 需求不足時貨留在來源

## F / F2 / F3 / NST — 目標驅動

以 Target 欄作為接收需求，優先滿足目標店；F 另外服務非目標的補 0 店。F2/F3/NST 只服務 Target 店，並在 RF 轉出上逐級收緊。

| 模式 | 非 Target 接收 | RF 轉出保留 | RF 上限 | 備註 |
|---|---|---|---|---|
| F | 補 0（total ≤ 1） | 不保留 | 不設 | 供應最進取 |
| F2 | 不處理 | 不保留 | 不設 | 集中補 Target |
| F3 | 不處理 | 保留 2 | 不設 | 高庫存優先 |
| NST | 不處理 | 保留 2 | 淨庫存 75% | 庫存 <3 不出 |

### F　目標優化

*先滿足 Target，再順手補 0。*

**何時用**：有明確的目標店／目標量（新店、重點店），同時想照顧其他缺貨店。

**輸入**：基本欄位、Target　**參數**：—

**來源**

- ND 無 Target 且淨 > 0 → 全轉（優先 1）。
- RF 無 Target 且淨 > 0、非最高銷量 → 全轉（優先 2，不保留 Safety）。

**可轉量**

- 可轉 = 全數淨庫存（F 不保留）。

**接收**

- Target > 0 的店（不論 ND／RF）→ 需求 = Target（優先 1）。
- 其他 RF 總 ≤1 → 補 0，目標 max(Safety×0.5, 3)（優先 2）。

**配對次序**

1. ND → Target 店
2. 同 OM RF → Target 店
3. 跨 OM RF → Target 店
4. RF → 補 0 店

**後處理**

- 配對後缺口填補
- 單件合併
- Target 達成分析

**不能處理的情景**

- 【設計】非 Target 缺貨店完全不處理，即使庫存 0。
- 【設計】只要該店任何一個 SKU 有 Target，該店全部 SKU 都不可作來源（全域保護），即使個別 SKU 嚴重過剩。
- 【邊界】Windy 目標優先只是排序懲罰（+5），不是硬性；Windy 來源不足時仍會用非 Windy 貨。
- 【設計】預設大 Target 優先，小 Target 可能永遠不足；可勾「優先滿足小型目標」。
- 【風險】ND 有 Target 亦可接收；上載警告與程式相反（見第 5 節）。

### F3　目標性補 0

*F2 加上 RF 保留 2 件、最高庫存優先。*

**何時用**：要補 Target，但不希望 RF 來源被清零；來源店仍有基本陳列。

**輸入**：基本欄位、Target　**參數**：—

**來源**

- ND 無 Target 全轉。
- RF 淨 > 2 才可出，可轉 = 淨 − 2。
- 排序：同優先級內按原始庫存降序（最高庫存先出），再按銷量升序。

**可轉量**

- ND：全數；RF：max(淨−2, 0)。

**接收**

- 只收 Target 店；需求 = Target。

**配對次序**

1. ND → Target
2. RF（同 OM 或跨 OM 同級） → Target

**後處理**

- 缺口填補
- 單件合併

- 【設計】Target 店全域保護同 F2：只要該店任何一個 SKU 有 Target，全部 SKU 都不可作來源。
- 【風險】ND 有 Target 亦可接收；上載警告與程式相反。

### NST　New Shop Target 調貨

**何時用**：新店／新目標店需要持續補貨，但要把來源店的風險降到最低。

**來源**

**接收**

**配對次序**

**後處理**

- 缺口填補（仍受 75% 與店數上限）

## ND1–ND4 — ND 互轉

打破「ND 不可接收」的全局規則，讓 ND 店舖之間互相補貨。ND1/ND2 以 2 倍銷量作接收上限；ND3/ND4 只補零庫存 ND，來源保留 3 件。

| 模式 | 接收對象 | 來源保留 | 跨 OM |
|---|---|---|---|
| ND1 | RF 緊急＋ND（2×銷量） | 不保留 | 否 |
| ND2 | 同 ND1 | 不保留 | 是 |
| ND3 | 零庫存 ND（含零銷量） | 保留 3 | 否 |
| ND4 | 零庫存且有銷量 ND | 無銷量全轉／有銷量留 3 | 否 |

### ND1　ND 同 OM 轉貨

*ND 之間互相補貨，按銷量決定先後。*

**何時用**：ND 店之間庫存不均，但不想牽動 RF 貨源。

**輸入**：基本欄位　**參數**：—

**來源**

- ND 淨 > 0 且非最高銷量。
- 按 Last Month + MTD 升序：0 銷優先出，其後銷量最低先出。

**可轉量**

- 全數淨庫存（不保留）。

**接收**

- RF 淨 0 且有銷量 → 補 Safety（或 2），優先 1。
- ND 有銷量且現有 < 2×總銷量 → 補到 2×總銷量，優先 2。
- 零銷量 ND 不可接收。

**配對次序**

1. ND → RF 緊急
2. ND → ND 潛在（2×銷量）

**後處理**

- 單件合併（同一來源多條線）
- 1 件線可保留

## 精簡 SKU — 超出上限即回收

為每個 RF 店舖設定存貨上限 Cap = max(Safety×2, 過去 2 個月銷量×2)，超出部分調往不足的店；配不完的退 D001。

| 模式 | 配對 | 剩餘去向 | 跨 OM |
|---|---|---|---|
| 精簡SKU(限同OM) | RF 補到 Cap | 退 D001 | 否 |
| 精簡SKU(跨OM) | RF 補到 Cap | 退 D001 | 是 |
| 精簡SKU(退D001) | 不配對 | 全數退 D001 | 不適用 |

### 精簡SKU(限同OM)　精簡 SKU（限同 OM）

*超過 Cap 的貨調給不足的店，配不完退 D001。*

**何時用**：要壓低整體存貨、統一把 RF 店維持在合理上限。

**輸入**：基本欄位、Last 2 Month Sold Qty（可選）　**參數**：—

**來源**

- ND：淨 > 0 全轉（優先 1）。
- RF：總 > Cap 且非最高銷量；可轉 = min(總−Cap, 淨)（優先 2）。

**可轉量**

- Cap = max(Safety×2, 過去 2 個月銷量×2)。
- 只出超過 Cap 的部分。

**接收**

- RF 總 < Cap → 補到 Cap（優先 1）。
- 每店最多收初始缺口。

**配對次序**

1. ND → RF 不足 Cap
2. RF 超 Cap → RF 不足 Cap
3. 剩餘 → D001

**後處理**

- 來源可轉 ≥2 才配對
- 剩餘退 D001；1 件不退

|---|---|---|---|---|---|---|---|---|
| HC701 | RF | 20 | 0 | 4 | 3+0 |  |  |  |
| HA702 | ND | 5 | 0 | 0 | 0+0 |  |  |  |
| HC703 | RF | 2 | 0 | 8 | 5+0 |  |  |  |
| KC704 | RF | 3 | 0 | 8 | 6+0 |  |  |  |

| 來源 | 接收 | 件數 | 來源類型 | 接收類型 | 來源轉後 |
|---|---|---|---|---|---|
| HC701 | HC703 | 12 | 精簡SKU RF轉出 | 精簡SKU接收 | 8 |
| HA702 | D001 | 3 | 精簡SKU ND轉出 | 退回D001 | 2 |
| HA702 | HC703 | 2 | 精簡SKU ND轉出 | 精簡SKU接收 | 0 |

**計算**：HC701 Cap = max(8, 6) = 8，可出 12；HC703 Cap = max(16, 10) = 16，欠 14 → 收 12；HA702 ND 5 件 → 2 件補 HC703、3 件退 D001。

**不能處理的情景**

- 【設計】配不完的貨退 D001；但只剩 1 件時不退（RF 與 ND 皆同），會留在店舖。
- 【設計】Supply source = 1 或 4 的來源不退 D001（留在店），文件未提。
- 【資料】Last 2 Month Sold Qty 缺失時回落 Last Month，Cap 可能偏低，導致過度轉出。
- 【設計】只同 OM；跨 OM 要用另一個模式。

### 精簡SKU(跨OM)　精簡 SKU（跨 OM）

*同限同 OM 的規則，但可跨 OM 補 Cap。*

**何時用**：本 OM 沒有不足 Cap 的店，但其他 OM 有。

**輸入**：基本欄位、Last 2 Month Sold Qty（可選）　**參數**：—

**來源**

- 同限同 OM：ND 全轉、RF 超 Cap 才出。

**可轉量**

- 同限同 OM。

**接收**

- 同限同 OM；跨 OM 時 Windy 只可轉 Windy，HD 不可到 HA/HB/HC。

**配對次序**

1. ND → RF 不足 Cap
2. RF 超 Cap → RF 不足 Cap
3. 剩餘 → D001

**何時用**：只想把多餘存貨收回倉，不需要店與店之間的調撥。

## 5　附錄：公式

| 項目 | 公式 / 規則 | 適用 |
|---|---|---|
| 總庫存 | SaSa Net Stock + Pending Received | 所有模式 |
| 有效銷量 | Last Month Sold Qty + MTD Sold Qty | 最高銷量保護、ND、Mix 保護 |
| A / A1 上限 | max(總×20%, 2)；轉後 ≥ Safety（單件上調例外） | A、A1 |
| B 上限 | max(總×50%, 2) | B、B2/B3 的 RF |
| C 上限 | min(int(總×30%), 自訂 3–10)，最少 1 | C、C1、C2 |
| 補 0 目標 | max(Safety×0.5, 3) | C、C1、C2、F P2、ND3、ND4 |
| ND 接收上限 | 2 ×（Last Month + MTD） | ND1、ND2 |
| NST RF 上限 | min(int(淨×75%), 淨−2)；淨 ≥3 | NST |
| 精簡 SKU Cap | max(Safety×2, 過去 2 個月銷量×2) | 精簡 SKU ×3 |
| Turnday | ceil(有效銷量 ÷ 覆蓋日數 × N)；零銷量 = 0 | Turnday 主體 |
| 覆蓋日數 | 上月日數 + MTD 日期日號 | Turnday 主體 |
